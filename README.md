# WordPress on Coolify - Docker Compose Stack

A production-ready, opinionated Docker Compose stack for running **WordPress with PHP-FPM, Nginx, MySQL 8.4, and Redis Object Cache** inside [Coolify](https://coolify.io/).

> **Recommendation:** Fork this repository and adapt the configuration files to your specific hardware, traffic patterns, and plugin requirements. This stack is a starting point, not a one-size-fits-all solution.

---

## What's Included

| Service | Image | Role |
|---------|-------|------|
| **Nginx** | `nginx:1.27-alpine` | Public-facing reverse proxy, static asset caching |
| **WordPress** | `wordpress:6.7-php8.3-fpm-alpine` | PHP-FPM application server |
| **MySQL** | `mysql:8.4` | Database with InnoDB tuning |
| **Redis** | `redis:7.4-alpine` | Object cache for WordPress |

## Quick Start

### 1. Fork & Customize (Recommended)

**Create a fork** of this repository so you can freely modify settings without losing upstream changes.

Then edit these files to match your server:

- **`fpm/www.conf`** - Adjust `pm.max_children` based on your RAM
- **`php/wp-custom.ini`** - Tune OPcache and memory limits
- **`mysql/wp-tuning.cnf`** - Scale InnoDB buffer pool for your workload
- **`nginx/default.conf`** - Add domains, SSL headers, or rate limiting

All files are heavily commented to guide your changes.

### 2. Deploy on Coolify

1. In Coolify, go to **Project -> Environment -> New Resource -> Docker Compose**
2. Select **From Repository** and point to your fork
3. Set **Base Directory** to `/`
4. Set **Docker Compose Location** to `docker-compose.yml`
5. Assign a domain to the **nginx** service
6. Fill in the required environment variables:

| Variable | Example | Required |
|----------|---------|----------|
| `WORDPRESS_DB_NAME` | `wordpress` | Yes |
| `WORDPRESS_DB_USER` | `wordpress` | Yes |
| `WORDPRESS_DB_PASSWORD` | `Str0ngP@ssw0rd!` | Yes |
| `WORDPRESS_TABLE_PREFIX` | `wp_` | optional |

> `SERVICE_PASSWORD_MYSQL` is auto-generated by Coolify as a magic variable.

### 3. Activate Redis in WordPress

After first deploy:
1. Log into WordPress admin
2. Install **"Redis Object Cache"** by Till Kruss
3. Go to **Settings -> Redis -> Enable Object Cache**

## Hardware Sizing Guide

The included configs are tuned for **6 GB RAM**. Adjust these values for your server:

| RAM | `pm.max_children` | `innodb_buffer_pool_size` | `opcache.memory_consumption` |
|-----|-------------------|---------------------------|------------------------------|
| 4 GB | 50 | 128M | 128 |
| 6 GB | 80 | 256M | 256 |
| 12 GB | 160 | 512M | 512 |
| 24 GB | 300 | 1G | 512 |

> Formula: `pm.max_children ~ (total_RAM * 0.4) / 65MB_per_process`

## Common Commands

```bash
# Check PHP-FPM applied config
docker exec <wordpress_container> php-fpm -tt 2>&1 | grep pm.max_children

# Reload PHP-FPM without restart
docker exec <wordpress_container> kill -USR2 1

# Reload Nginx without restart
docker exec <nginx_container> nginx -s reload

# Monitor Redis in real-time
docker exec <redis_container> redis-cli monitor

# MySQL slow query log (if enabled)
docker exec <mysql_container> mysql -e "SHOW VARIABLES LIKE 'slow_query_log';"
```

## Post-Deploy Checklist

- [ ] Redis Object Cache plugin installed and enabled
- [ ] Domain resolves correctly to the Nginx service
- [ ] HTTPS/SSL configured via Coolify proxy (Traefik/Caddy)
- [ ] `php-fpm -tt` confirms your custom `www.conf` values
- [ ] MySQL `SHOW VARIABLES` confirms `innodb_buffer_pool_size`
- [ ] WordPress admin loads without PHP warnings

## Troubleshooting

| Symptom | Likely Cause | Fix |
|---------|--------------|-----|
| `pm.max_children = 5` still shown | `www.conf` not in volume yet | Run `tee` inside container or redeploy |
| 500 errors after plugin install | `WP_CACHE` already defined | Use `if (!defined('WP_CACHE'))` in compose |
| Slow admin/dashboard | Too many autoloaded options | Clean `wp_options` transients or delegate to Redis |
| High memory usage | `pm.max_children` too high | Lower based on actual per-process RAM |
